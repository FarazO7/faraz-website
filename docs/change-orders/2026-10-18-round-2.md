### Item 2: full-width, continuously moving carousels
- **Root cause.** The track sits inside `.wrap`, the content column, and moves by snapping one card at a time (round 1, on purpose).
- **Change, in the shared `components/Carousel.tsx`, so both sections get it:**
  - **Full width.**
    - The track breaks out of the column: `width: 100vw; margin-inline: calc(50% - 50vw)`.
    - `main` gets `overflow-x: clip`, which trims the scrollbar's share of `100vw`. That means no horizontal page scroll, while `position: sticky` still works (clip is not a scroll container).
    - The label, heading and controls stay in the column.
    - Card widths are derived from the column width, so they don't change.
  - **Continuous drift.**
    - The original cards plus three `aria-hidden`, inert copies, enough to fill a 2560px screen.
    - The drift runs left at `DRIFT_PX_PER_S = 35`, one constant at the top of the file for you to tune.
    - It wraps one set-width back when it passes the second copy, which is invisible because the copies are identical.
    - **Smoothness.** The whole-pixel part of the position goes into `scrollLeft` and the fraction into a `translateX` on the track, so it moves in sub-pixel steps without stutter. Native swipe and trackpad scrolling keep working.
    - Scroll snap is off. The round-1 "still row" rule is dropped, so both carousels always move.
  - **Pausing.** The drift stops, and resumes about two seconds after the interaction ends, easing back up to speed rather than jumping:
    - the pointer is over the carousel;
    - touch, scroll or drag;
    - keyboard focus on a card;
    - an open menu inside a card (Zomato's "View 4 documents", detected by `aria-expanded="true"`);
    - the carousel is off-screen;
    - the tab is hidden.
  - **Controls.** The pause/play button and the arrows stay. An arrow moves one card, then the drift continues from there.
  - **Reduced motion.** No automatic movement; the arrows and swipe work.
  - **Kept.** Card sizes, card order (NextLeap first), and previews never cropped.
- **Files.** `components/Carousel.tsx`, `app/globals.css`, `app/page.tsx` (`main` clip). `CaseStudies.tsx` and `Skills.tsx` change only their `itemClassName` widths.

### Item 5: the "1 Issue" script error
- **Root cause (confirmed).** `components/Hero.tsx` renders `<script dangerouslySetInnerHTML={HERO_FITS_JS}>`, the pre-paint layout decision I added in the redesign's review fixes. React never executes scripts rendered by components on the client and warns about it in development. It only worked on the first server-rendered load.
- **Fix: CSS, no script.** The decision was "is there motion, and does the hero copy fit one screen". The copy's height only varies with width, and I measured it across widths: 320 → 731px, 390 → 679, 768 → 571, 1024 → 597, 1366 → 669, 1440 → 683, 1920+ → 725. So `@media (prefers-reduced-motion: no-preference) and (min-height: 750px)`, combined with the `js` class the root layout already sets before first paint, decides the layout in pure CSS, before first paint, on every load and navigation.
  - All three of your sizes get the scroll stage (785, 768, 844 ≥ 750).
  - Anchors (`/#work`) and mid-page reloads land correctly, because there's no late layout switch.
  - `HeroStage` keeps only the scroll-driven variables and reads the same media query with `matchMedia`, re-measuring when it changes.
  - `lib/heroFit.ts` and `HERO_FITS_JS` are deleted.
- **Safeguard.** The content guard fails the build if any file in `components/` contains `<script`.
- **Files.** `components/Hero.tsx`, `components/HeroStage.tsx`, `lib/heroFit.ts` (deleted), `app/globals.css`, `scripts/check-content.ts`.
